## 목적과 독립 가드레일

이 문서는 [장간 교차형 사이드 콘텐츠 저작 계약](../contracts/interleaved_side_content_authoring.md)을 따르는 신규 SQ 5개, 각 4장, 총 20장의 authoring blueprint다. 완성 대사·연출본이나 runtime YAML·코드가 아니며, 수치·발생률·실제 효과는 후속 handoff에서 확정한다.

- 메인 장, 다른 SQ, RI 약 7개, 장기 중단이 어느 장 사이에 끼어도 된다. 같은 SQ는 한 메인 구간에 최대 1장만 후보가 된다.
- 전투·추격·활성 재난·인질·치료·부패 단서는 발생한 장 안에서 닫는다. 다음 장은 약속, 계절, 견본, 공고, 주소, 회신처럼 시간에 강한 anchor로만 연다.
- 천기록·서하린·청류문·객패귀로·혈월교·흑사방·사도 및 main/true-ending flag와 무관하다. 일회 NPC와 독립 소세력의 로컬 상태만 쓴다.
- 일리아스·오디세이 오마주, 모욕과 출전 거부, 빌린 신분, 성벽 가족, 적 시신 반환, 장례 경기, 역병 약사, 휴전 화살, 운구·판정 중심 갈등을 반복하지 않는다.
- 보상 분류는 스킬, 기연, 칭호, 인물 호감도, 단체 호감도, 아이템·소모품, 퀘스트 아이템, 패물(佩物), 기억 파편만 사용한다. 각 장의 3보상은 선택별 일반 배타이며 수치 미확정이다. 호감도는 이 문서의 로컬 인물·단체에만 적용한다.
- 완료 장 중복은 1~2문장 recap과 anchor 재안내로 소비한다. 미완료 장 누락은 재후보화하며 건너뛰어 후속 장을 열지 않는다. 포기·실패도 위험 없는 fallback으로 닫고 메인 진행을 막지 않는다.

## SQ01 — 밤에만 도는 빈 방앗간

- stable line ID: `wuxia_side_v2_01_night_mill`
- 장르/핵심 질문: 생활 추리. 효율과 소유권의 기록에서 빠진 노동을 누구의 것으로 인정할 것인가.
- 독립성 선언: 산간 물방앗간과 일회 NPC만 쓴다. 메인 정보·세력·엔딩·다른 SQ 단서를 열거나 잠그지 않는다.
- 등장인물: 방앗간 주인 **송겨**(고장과 체면을 함께 두려워함), 전 공동주인 **연비**(청력을 잃었으나 손의 감각이 뛰어남), 견습 **모진**(둘을 화해시키려다 거짓말이 늘어남), 산촌 부엌계 주민들.
- 전체 4장 흐름: 빈 맷돌의 원인 조사 → 비공식 야간 노동 발견 → 가뭄철 물·노동 배분 결정 → 추수 뒤 운영 방식 결산.
- line-level 상태: `mill_evidence_method`, `night_labor_stance`, `water_share_model`, `mill_ending`, `song_gyeo_trust`, `yeonbi_trust`, `village_kitchen_trust`.
- 배치·이탈·재플레이: 초반~중후반 어느 범용 산촌 구간에도 진입 가능하며 인접 메인 구간 연속을 강제하지 않는다. 최소 공백은 ‘다른 콘텐츠 1개 이상 권장’, 최대 공백은 ‘무제한’이다. 포기 시 마지막 잠긴 수문·게시된 운영안에 머물며, 재플레이는 증거 방식과 운영 주체 조합을 바꾼다.
- 결말 변주: 공동 운영이면 생산량은 안정되나 합의 비용이 남고, 분리 운영이면 자율성 대신 물길 경쟁이 남으며, 기술 전수형이면 두 장인의 이름은 흐려지나 견습의 미래가 열린다. 어느 결말도 메인 자원이나 true ending을 바꾸지 않는다.

### `wuxia_side_v2_01_c01_empty_stone` — 빈 맷돌의 새벽

- eligibility: 라인 미진입, 산촌·계곡길의 낮. 메인/SQ 플래그 불필요.
- 복귀 문장: 산촌 소문은 곡식 없는 맷돌이 새벽마다 돈다고 전한다. 플레이어가 도착했을 때 방앗간은 낮 영업 중이며 급한 사고는 없다.
- 상황과 local goal: 곡식을 넣지 않은 맷돌이 새벽마다 젖은 가루를 토하고, 송겨는 귀신보다 수리비를 걱정한다. 모진은 밤에는 아무도 없었다고 지나치게 빠르게 말한다. 목표는 사람을 범인으로 단정하지 않고 맷돌이 돈 흔적을 하나 확정하는 것이다.
- 정확히 3개 선택과 immediate result:
  1. 물살·톱니·축의 작업 순서를 업무 흐름처럼 재구성한다. 낡은 보조축이 밤마다 연결됐다는 마모를 찾고 송겨는 체면을 지킨다.
  2. 해 질 때까지 기다려 물레의 진동을 몸으로 읽는다. 귀가 아닌 손으로 박자를 맞춘 누군가의 흔적을 알아내며 연비의 존재를 먼저 감지한다.
  3. 모진에게 벌 대신 하루 휴식을 약속하고 묻는다. 그가 가난한 집의 거친 곡식을 밤에 갈아 주었다고 털어놓지만 배후의 장인은 말하지 않는다.
- 공통 immediate crisis closure: 보조축을 분리하고 수문을 잠가 빈 맷돌은 이 장 안에 멈춘다. 끼임·범람·추적 위험은 남지 않는다.
- delayed result: 선택에 따라 송겨·연비·모진의 첫 신뢰와 주민 소문만 달라진다.
- stable exit: 방앗간은 낮 운영만 가능한 안전 상태가 되고 플레이어는 자유롭게 떠난다.
- 다음 장 비긴급 hook: 송겨가 다음 무월밤에 다시 확인해 달라는 날짜 없는 쪽지를 주며, 마모 견본은 방앗간 상자에 보관된다.
- 재개 조건/실패·이탈 fallback: `mill_c01_complete`와 쪽지 또는 상자 사본으로 c02를 연다. 조사 실패·이탈 시에도 보조축 분리와 수문 잠금은 유지되고 주민은 낮 방앗간을 쓴다.
- 선택별 보상(일반 배타, 수치 미확정): ① 스킬 **수차공정도**(보통, 복잡한 작업의 병목을 순서로 읽음) ② 기연 **손끝으로 듣는 물소리**(희귀, 감각을 바꿔 흔적을 이해함) ③ 인물 호감도 **견습 모진**(보통, 처벌보다 솔직함을 택한 관계).
- local flags/state: `mill_c01_complete`, `mill_evidence_method=flow|vibration|confession`, 해당 인물 trust 1종.
- 대사 저작 가이드: 송겨는 비용을 사물 탓으로 돌리고, 모진은 짧게 변명한다. 반드시 ‘맷돌은 멈췄다’와 다음 확인은 급하지 않음을 전달한다. 현대식 공정 분석을 강의처럼 설명하지 않는다.

### `wuxia_side_v2_01_c02_flour_dust_shift` — 달빛 아래 두 번째 교대

- eligibility: c01 완료 후 다른 메인 구간, 무월밤 또는 흐린 저녁. 중간 공백 무제한.
- 복귀 문장: 빈 맷돌을 멈춘 방법과 방앗간 상자에 남은 마모 견본을 되짚는다. 송겨의 쪽지는 밤 확인이 급한 의무가 아니었음을 상기한다.
- 상황과 local goal: recap으로 빈 맷돌을 멈춘 방식과 보관된 흔적을 한두 문장 상기한다. 약속한 밤, 청력을 잃은 연비가 버려질 거친 곡식을 몰래 갈고 있으며 모진이 수문을 열어 주는 모습이 드러난다. 목표는 야간 노동을 즉시 중단시킨 뒤 그 행위를 절도·구휼·공동 권리 중 어떻게 다룰지 정하는 것이다.
- 정확히 3개 선택과 immediate result:
  1. 연비와 송겨를 같은 자리에 불러 과거 동업 약속을 확인한다. 송겨는 화를 내지만 연비의 지분을 부정하지는 못한다.
  2. 그날의 거친 곡식만 끝까지 갈아 주민에게 나누고, 이후 야간 사용을 금한다. 주민은 안도하고 송겨는 손해를 분명히 기억한다.
  3. 연비의 손동작을 모진에게 전수하게 하고 작업을 낮으로 옮긴다. 비밀 구휼은 끝나지만 기술의 주인이 누구인지 새 갈등이 생긴다.
- 공통 immediate crisis closure: 그 밤의 곡식은 안전하게 처리되고 수문은 잠긴다. 야간 작업자는 귀가하며 다음 장 전까지 몰래 맷돌을 돌리지 않기로 한다.
- delayed result: 구휼 곡물 가격, 세 NPC의 로컬 호감도, ‘도둑 방앗간/어진 방앗간/새 견습’ 소문만 변한다.
- stable exit: 연비는 자신의 집, 모진은 숙소, 송겨는 잠긴 방앗간에 머문다.
- 다음 장 비긴급 hook: 세 사람이 가뭄철 첫 물배분 날에 의견을 듣겠다는 공동 약속패를 방앗간 문 안쪽에 건다.
- 재개 조건/실패·이탈 fallback: `mill_c02_complete`와 문 안 약속패로 c03을 연다. 협의 실패·이탈 시 야간 사용 금지와 주민용 낮 교대가 fallback으로 유지된다.
- 선택별 보상: ① 퀘스트 아이템 **닳은 동업 목패**(희귀, 후속 recap용이며 분실 시 방앗간 사본 존재) ② 칭호 **한 밤의 품삯을 본 자**(희귀, 실리와 구휼을 함께 감당함) ③ 스킬 **무언전수 수결**(희귀, 말 없이 손기술을 나누는 방식).
- local flags/state: `mill_c02_complete`, `night_labor_stance=restore|allow_once|transfer`, trust 변화.
- 대사 저작 가이드: 연비는 손짓과 짧은 필담, 송겨는 소유권 어휘, 모진은 ‘굶는 집’을 먼저 말한다. 연비를 신비한 장애인 현자로 만들지 말고 노동의 대가를 명시한다.

### `wuxia_side_v2_01_c03_water_share` — 물 한 칸, 품 한 칸

- eligibility: c02 완료, 건기 소문이 열린 뒤. 실제 시간제한 없음.
- 복귀 문장: 야간 노동을 닫은 방식과 세 사람이 문 안에 건 공동 약속패를 되짚는다. 건기 소문은 배치 창일 뿐 즉시 대응 요구가 아니다.
- 상황과 local goal: recap은 야간 사용을 닫은 결정과 문 안의 약속패를 상기한다. 가뭄으로 낮 수량도 줄자 송겨는 시장 곡식, 연비는 거친 곡식, 모진은 수리 시간을 우선하자고 한다. 목표는 이번 건기의 물길과 노동 배분안을 하나 채택해 방앗간을 안전 운용 상태로 만드는 것이다.
- 정확히 3개 선택과 immediate result:
  1. 시장·구휼·정비를 번갈아 배치하는 순환표를 만든다. 모두 조금씩 손해 보지만 물길 충돌이 사라진다.
  2. 송겨와 연비에게 수문 시간을 분리하고 각자 품삯을 받게 한다. 책임은 선명해지나 협업 이점은 줄어든다.
  3. 모진에게 하루 운영권을 주고 두 장인은 고장 난 축만 함께 고치게 한다. 생산은 느리지만 세대교체 가능성이 보인다.
- 공통 immediate crisis closure: 선택한 배분으로 당일 곡식은 모두 안전하게 회수되고 수문 표식이 설치된다. 굶는 집이나 터진 물길을 남기지 않는다.
- delayed result: 마을 가루 가격, 방앗간 평판, 세 사람의 로컬 호감도만 변한다.
- stable exit: 건기 운영안이 게시되고 누구도 플레이어의 즉시 감독을 요구하지 않는다.
- 다음 장 비긴급 hook: 첫 수확 뒤 운영 결과를 알리는 봉한 곡분 견본 세 봉지가 객잔 보관함에 맡겨진다.
- 재개 조건/실패·이탈 fallback: `mill_c03_complete`와 곡분 견본 또는 객잔 보관 기록으로 c04를 연다. 합의 실패 시 시장·구휼·정비가 최소 1칸씩 배정된 임시 순환표로 건기를 넘긴다.

- 선택별 보상: ① 칭호 **철을 기다리는 검객**(희귀, 힘보다 계절을 존중) ② 스킬 **휴매삼음검**(희귀, 폭발력 감소와 생태 안전·제어 향상의 trade-off) ③ 단체 호감도 **대숲 공생회**(희귀, 분산 공동체의 로컬 신뢰).
- local flags/state: `grove_c04_complete`, `grove_ending=seasonal|adapted|distributed`, `grove_line_closed=true`.
- 대사 저작 가이드: ②를 단순 상위 무공으로 쓰지 말고 위력 trade-off를 말한다. 마지막 울음은 후속 위험 신호가 아니라 회복된 계절음이다.

## 장간 배치·복구 계약

| 항목 | canonical authoring 동작 |
|---|---|
| 진입 | 각 line c01은 메인 플래그 없이 범용 지역에서 독립 후보화한다. 한 구간 활성 SQ는 전체 scheduler 기대 1~2개이며 고정 quota가 아니다. |
| 순서 | line 내부 c01→c02→c03→c04만 지킨다. 서로 다른 line끼리의 순서는 보장하지 않는다. |
| 같은 구간 | 같은 SQ의 장을 한 메인 구간에 2개 배치하지 않는다. 다른 SQ·RI가 얼마든지 사이에 낄 수 있다. |
| 누락 | 아직 완료하지 않은 가장 이른 장을 다음 적합 구간에 재후보화한다. 누락을 완료로 간주하거나 후속 장을 먼저 열지 않는다. |
| 중복 | 완료 장은 본문·보상을 반복하지 않고 1~2문장 recap, 현재 anchor 위치, 미완료 다음 장만 안내한다. |
| 포기 | 각 stable exit에서 line을 비활성화할 수 있다. 보관소 사본·공고·주소는 남되 위험·빚·추격·치료 의무는 남기지 않는다. |
| 재개 | 해당 장의 eligibility와 직전 durable hook만 확인한다. 소지품이 사라졌다면 NPC·화실·객잔·작업장 사본으로 복구한다. |
| 완료 | c04 뒤 line은 닫힌다. 후일담은 소문·가격·안전한 편지·간판·공고·로컬 호감도 대사만 허용한다. |

## Acceptance tests

각 테스트는 5개 line과 20개 chapter 전부에 적용한다.

1. **delay test — PASS 조건:** 임의의 연속 두 장 사이에 메인 1장, 다른 SQ 1장, RI 7개와 장기 중단을 삽입해도 다음 장의 recap·사본 anchor만으로 인물·결정·local goal을 복구한다. 진행 중 전투·치료·불·떼·실종자가 있으면 FAIL.
2. **reorder test — PASS 조건:** 다섯 line의 같은 번호 장을 임의 순서로 교차해도 서로의 NPC·flag·아이템을 요구하지 않는다. 다른 line의 결과가 eligibility에 들어가면 FAIL.
3. **stop test — PASS 조건:** 20개 각 장의 stable exit 직후 게임을 끝내도 사람·영물·작품·시설이 안전 custody에 있고 즉시 행동 요구가 없다. 열린 추격·재난·시간제한이 있으면 FAIL.
4. **abandonment test — PASS 조건:** c01·c02·c03 어느 stable exit에서 포기해도 메인과 다른 SQ가 계속되며, 로컬 NPC는 해당 fallback 상태에서 생업을 유지한다. 강제 빚·보복·치료 의무가 남으면 FAIL.
5. **missing chapter test — PASS 조건:** scheduler가 중간 장을 누락하면 그 장만 재후보화하고 후속 장은 잠긴다. 누락 장의 정보를 요약으로 자동 획득하면 FAIL.
6. **duplicate event test — PASS 조건:** 완료 장 재호출은 recap·anchor 복구만 제공하고 선택·보상·위기를 재생하지 않는다. local flag나 배타 보상을 중복 지급하면 FAIL.
7. **no hidden gate test — PASS 조건:** 모든 필수 단서와 anchor는 해당 line 내부에 사본·대체 경로가 있고, RI·메인·다른 SQ·true-ending state를 요구하지 않는다. 외부 이벤트 하나가 없어서 라인이 막히면 FAIL.
8. **choice count test — PASS 조건:** 각 장은 정확히 3선택이며 각 선택에 즉시 결과와 서로 배타적인 보상 1개가 있다. 선택 수가 변하거나 한 선택이 다른 선택 보상을 함께 주면 FAIL.
9. **finality test — PASS 조건:** 각 c04는 line-level 결말 flag를 기록하고 후속 위기 없이 종결한다. c05를 암시하거나 ‘곧 다시 모이라’고 요구하면 FAIL.

## Authoring review checklist와 runtime handoff 경계

- [ ] stable line ID 5개, stable chapter ID 20개가 design_source 전체에서 유일하다.
- [ ] 각 line은 정확히 4장이며 각 장에 eligibility, 2~4문장 상황/local goal, 정확히 3선택과 immediate result가 있다.
- [ ] 20개 장 모두 공통 immediate crisis closure, delayed result, stable exit, durable hook, 보상 3개, local state, 대사 가이드가 있다.
- [ ] SQ01~05의 장르·장소·갈등 장치·감정 종결이 서로 다르고 Iliad/Odyssey 및 기존 imported side 소재를 반복하지 않는다.
- [ ] 현대인 관찰은 공정 흐름, 비교 실험, handoff, 현장판 갱신으로 드러나며 스마트폰·인터넷 해결이 없다.
- [ ] 폭력·비폭력 어느 하나가 자동 정답이 아니고, 선택마다 품질·비용·자율·관계·생태 중 다른 손실이 있다.
- [ ] 로컬 호감도만 사용하며 main/true-ending gate·핵심 세력·필수 진행을 읽거나 쓰지 않는다.
- [ ] 보상 taxonomy·등급·이름 톤·배타성이 정본과 맞고 수치는 미확정이다.
- [ ] 대사 저작자는 욕망·말투·필수 정보·금지 설명조를 지키되 완성 대사는 별도 authoring 산출물에서 작성한다.
- [ ] runtime handoff 시 scheduler eligibility, completed/abandoned flag, anchor recovery, duplicate recap, reward mapping, safe-closure QA를 별도 스키마로 승인한다.

이 문서는 `authoring_review_required`이며 runtime 구현 완료를 선언하지 않는다. authored events, YAML, scheduler 코드, bundle, 수치 밸런스는 후속 승인 범위다.
