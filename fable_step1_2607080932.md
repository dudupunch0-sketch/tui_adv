## 0. What this refactor is and is not

This is a **behavior-preserving refactor**. The observable behavior of every
binary, wasm export, web page, and script must be byte-identical before and
after. You are reorganizing code, removing duplication, and hardening fragile
spots. You are NOT redesigning anything, NOT adding features, and NOT changing
any output text.

### 0.1 Hard invariants — never violate these

1. **Rust GameCore (`crates/escape-core`) owns all game rules.** Never move
   game logic into a renderer (terminal, web) and never move renderer logic
   into `escape-core`. "Core owns truth. Renderer owns mood."
2. **Do not change any user-visible string.** Tests assert exact Korean output
   text, exact error messages, exact JSON field names. When you extract a
   string into a constant, the constant's value must be byte-identical to the
   original literal.
3. **Do not change any serialized JSON shape.** `ScenePage`, `ActionResult`,
   `GameState`, `SaveEnvelope`, content bundle schema, and the wasm
   JSON-string boundary are frozen wire contracts.
4. **Do not touch content data.** Never edit anything under
   `crates/escape-core/fixtures/`, `web/src/data/generated/`,
   `src/tui_adv/data/`, `src/tui_adv/storypack-previews/`, or any `.yaml` /
   `.bundle.json` file.
5. **Do not change localStorage keys or their values.** The live keys are
   `igu-hakji.rust.save.v1`, `igu-hakji.last-run-summary.v1`,
   `tui-adv.player-settings.v1`, plus legacy keys `escape-office.save.v1` and
   `escape-office.rust.save.v1`.
6. **Do not add new dependencies.** No new crates in any `Cargo.toml`, no new
   npm packages, no new Python packages. (Adding internal modules/files is
   fine and expected.)
7. **Do not edit documentation** under `docs/`, `idea_box/`, `README.md`, or
   `AGENTS.md` except where a work package explicitly says so.
8. **Do not rename or remove any public API** (anything `pub` re-exported from
   `crates/escape-core/src/lib.rs`, any exported symbol in `web/src/*.ts`, any
   CLI flag of `escape-terminal`) except where a work package explicitly says
   so.
9. **Do not change CLI flag names, flag semantics, exit codes, or stderr/stdout
   text** of `escape-terminal` or `scripts/export_web_data.py`. 63 CLI smoke
   tests assert exact output.

## 1. Current-state summary (why each work package exists)

Sizes at baseline: `crates/escape-core/src/final_epilogue.rs` 1536 lines,
`crates/escape-terminal/src/main.rs` 1073 lines, `turn.rs` 731, `content.rs`
698, `scene_page.rs` 534, `web/src/main.ts` 405, `web/src/ui/storybook/render.ts`
408, `scripts/export_web_data.py` 322.

Main problems found in the audit:

- `final_epilogue.rs` mixes six responsibilities in one file and contains a
  505-line function (`build_candidates`) plus card body strings copy-pasted up
  to 4 times.
- `escape-terminal/src/main.rs` mixes seven responsibilities (CLI parsing,
  validation, bundle paths, headless printing, TUI snapshots, GlyphFX,
  interactive loops) and has action-line formatters triplicated.
- `content_bundle_start_location` is duplicated verbatim in
  `escape-terminal/src/main.rs:182-189` and `escape-wasm/src/lib.rs:65-72`.
- Resource-name match ladders (`"health" | "sanity" | ...`) are repeated in 3+
  places in `turn.rs` and again in `scene_page.rs`.
- `final_epilogue.rs` uses fragile positional indexing (`entries[1]`,
  `candidate_values[0]`) that will silently corrupt output if a list is
  reordered.
- `web/src/main.ts` is a single-module controller with 11 module-level mutable
  globals, a 10-branch string dispatcher, and duplicated event-wiring loops.
- Web localStorage keys and schema versions are scattered across
  `startScreen.ts` and `playerSettings.ts`; one exported key
  (`SETTINGS_KEY = 'igu-hakji.settings.v1'`) is dead (never read anywhere).
- Small helpers are duplicated across web files (`errorMessage`, `StorageLike`,
  `DEFAULT_SEED = 123`).
- `scripts/export_web_data.py` has two near-identical check functions and a
  repeated "print stale errors" block.

Test safety net (all green at baseline): 16 core contract tests, 10 content
bundle tests, ~24 route parity tests, 34 wasm JSON contract tests, 63 terminal
CLI smoke tests, 10 web vitest files, root `tests/` pytest suite.

#### WP-A3: remove fragile positional indexing in the epilogue audit

**Problem (baseline `final_epilogue.rs`):**
1. L325-335 (`canonical_state_audit`): the code builds a `Vec<AuditEntry>` and
   then reads/reassigns `entries[1]` assuming index 1 is the
   "boss_resolution_route" slot. If someone reorders the list, this silently
   corrupts output.
2. L362 (`resolve_state`): `let value = candidate_values[0];` is safe only
   because of an `is_empty()` early-return at L352 — refactor-fragile.

**Steps:**
1. In `audit.rs`, replace the `entries[1]` access with a lookup by the entry's
   key/name field: find the entry whose identifying field equals the exact
   string currently at position 1 (read the code to get the field name and the
   exact string — it is the "boss_resolution_route" entry). Use
   `entries.iter_mut().find(|e| e.<field> == "<exact string>")`. If not found,
   keep current behavior semantics: since today index 1 always exists, the
   `find` will always succeed; still, handle `None` by doing nothing (no
   panic) rather than unwrapping.
2. Replace `candidate_values[0]` with
   `let Some(&value) = candidate_values.first() else { <same early behavior as the is_empty branch> };`
   or keep the existing `is_empty` early-return and change the index to
   `candidate_values.first().copied()` + `expect`-free handling. The resolved
   behavior for non-empty input must be identical.

**Must not change:** the emitted audit text, ordering of audit entries, or any
routing result.

**Verify:** `cargo test --workspace` (route_parity audit-collapse test is the
guard).
