# 07. 천기록 / 천외편린 보상

소유자: 두현 황

# 문서 목적

이 문서는 `천기록`과 `천외편린` 보상 구조를 관리한다.

---

# 천기록의 정의

천기록은 검색창이 아니다.

플레이어가 원하는 지식을 직접 찾는 시스템이 아니라, 조건을 만족했을 때 랜덤 현대지식 후보를 보상으로 제시하는 장치다.

---

# 천외편린 구조

```
후보 3개 중 하나만 선택한다.
```

예:

```
상대의 보법을 본다.
↓
청류안이 중심 이동을 읽는다.
↓
천기록이 천외편린 후보를 제시한다.

1. 복싱 풋워크
2. 출근길 인파 피하기
3. 산업안전 작업동선
```

선택 결과:

```
청류문 보법의 소실된 일부가 현대 감각으로 복구된다.
```

# 메리 수 방지

```
본다고 바로 배우는 것이 아니다.
몸이 따라가지 못하면 부상 / 기혈 역류 / 심마 위험이 생긴다.
청류안은 피로와 집중을 크게 소모한다.
상대가 너무 고수면 구조는 보여도 몸이 이해하지 못한다.
천기록은 정답을 주지 않고 후보 3개만 준다.
잘못된 편린을 고르면 이상한 응용이나 부작용이 생긴다.
남의 무공을 읽는 능력은 정치적으로 위험하다.
```

---

# 무명과의 연결

무명은 남의 무공을 빠르게 훔쳐 덧씌우는 카피를 사용한다.

주인공의 천외편린은 무명의 카피와 대비된다.

```
무명:
남의 흐름을 훔친다.

주인공:
흐름을 이해하고 자기 몸에 맞게 재구성한다.
```

---

# 보스와의 연결

보스는 무공의 흐름보다 사람의 약점과 조직의 흐름을 읽는다.

천기록 / 청류안이 강해질수록, 주인공은 단순 기술 파훼가 아니라 사람과 조직의 약점까지 보게 될 위험이 있다.

이 지점이 침식 루트와 연결된다.

```
- 무명과 대비되는가?
- 침식 / 심마 위험과 연결되는가?
```

# 천기록 관련 존재

## 확정 방향

천기록은 **인격처럼 보이는 기록(B안)** 으로 둔다.

초반에는 시스템처럼 보이지만, 중후반부에 누군가가 적고 있다는 것을 눈치챌 수 있게 한다.

단, 정체는 끝까지 밝히지 않는다.

---

## 작동 원칙

### 초반

```
천기록은 검색창이 아니다.
질문에 답하지 않는다.
대화 상대가 아니다.
조건을 만족하면 현대지식 후보 3개를 보여준다.
플레이어는 그중 하나만 고른다.
```

### 중후반

```
천기록의 문장이 단순 기록이 아닌 것처럼 보이기 시작한다.
누군가 관찰하고, 고르고, 적고 있다는 느낌이 생긴다.
하지만 그 정체는 끝까지 밝혀지지 않는다.
```

---

## 문장 예시

```
[이번에는 더 오래 버텼다.]

[이 선택은 이전에도 기록된 적이 있다.]

[너는 아직 돌아갈 이름을 잃지 않았다.]

[기록자는 대답하지 않는다. 다만 다음 장을 넘긴다.]

수첩의 빈 줄 위로 먹물이 번졌다.
처음에는 점 하나였다.
곧 짧은 획이 되었고,
마지막에는 네가 묻지 않은 질문이 되었다.

[너는 아직 돌아가고 싶은가?]

너는 대답을 쓰지 않았다.
하지만 다음 줄은 이미 젖어 있었다.
```

```yaml
      - 기록자는 세계관을 설명하지 않는다.
      - 기록자는 정답을 주지 않는다.
      - 대화는 성립하지만, 정체 해명은 성립하지 않는다.

  final_policy:
    - 기록자의 정체는 끝까지 미공개.
    - 설명보다 여운과 불안을 남긴다.
```

# 2026-07-16 runtime 대조 보충

이 문서의 3택 천외편린·기록자 정체·부작용 설계는 장기 설계 원문이다. 현재 GameCore가 실제로 확정한 범위는 다음과 같다.

- 기존 `wuxia_cheonggi_record_first_fragment`와 `wuxia_cheonoe_pyeonrin_first_reward`/`second_reward`는 flags, clues, logs, presentation 중심의 preview grammar다. 선택이 즉시 수치 능력치나 재사용 가능한 보상 테이블을 열지는 않는다.
- Slice 3의 `insights`는 천외편린 3택 전체를 대체하는 시스템이 아니라, 사건 outcome으로 얻는 **영구 판정 보너스(+1~+2)** 를 표시하는 별도 경량 계약이다. 판정 합계와 사전 성공 확률에 코어에서 반영하고, Web은 `ScenePage`를 표시한다.
- 검증된 runtime에는 `insight_breathe_before_bargain`, `insight_read_the_flow`, `insight_name_the_rule` 세 기연과 기존 사건의 `add_insights` 연결이 있다. 이는 현재 Notion 15번 DB의 `낙법의 요령`, `청류심법 입문`, `복기의 습관`과 ID/명칭/보너스/획득 사건이 다르므로, 설계 의도를 확인하기 전에는 DB 원문을 자동 교체하지 않는다.
- 레벨링 runtime은 `runtime.leveling.thresholds: [30, 75, 120]`이며, 포인트를 `train:{ability_id}`로 배분하고 능력치 상한은 5다. C1 exporter·fixture·parity 검증과 D2의 Rust/Web/WASM/visual QA 검증 및 커밋이 완료되어 기본 preview 계약에 반영되었다.
- 구현 완료·미완료 판정과 repo 기준 커밋은 `13. 런타임 시스템 현황 (repo 동기화)`를 따른다.
