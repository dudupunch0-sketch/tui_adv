# 문서 목적

이 문서는 사건 카드 DB를 어떻게 운영할지 정의한다.

사건 카드는 `이구학지 — 천기록`의 스토리 관리 기본 단위다.

---

# 사건 카드의 역할

사건 카드는 다음을 관리한다.

```
언제 발생하는가
어떤 조건으로 열린다
누구와 관련되는가
어떤 세력을 움직이는가
어떤 선택지를 제공하는가
어떤 보상을 준다
어떤 후일담 카드와 연결되는가
엔딩에 어떤 영향을 주는가
```

# 운영 원칙

```
1. 새 아이디어는 먼저 사건 카드로 추가한다.
2. 긴 문서에 바로 녹이지 않는다.
3. 사건 카드가 충분히 쌓이면 루트 문서에 반영한다.
4. 모든 사건이 후일담을 갖지는 않는다.
5. 후일담 가치가 있는 사건만 후일담 카드로 연결한다.
6. 검수 상태를 반드시 사용한다.
```

# 2026-07-16 runtime 계약 보충

이 문서는 카드 운영 원칙을 소유하고, 실제 런타임 필드의 정본은 repo의 `crates/escape-core/src/content.rs`와 `docs/design/Event_Stage_Content_Model.md`가 소유한다.

## 사건/이벤트 구조

- Encounter는 `id`, `phase`, `conditions`, `choices`, `repeatable`, `weight`를 가진다.
- 선택지는 `id`, `label`, `conditions`, `cost`, `outcome`, 선택적 `check`를 가진다.
- `check`는 6능력치 중 하나와 난이도를 가지며, 성공/실패 각각 별도 outcome을 둔다. 판정은 `2d6 + 능력치`이고 선택지에 성공 확률을 미리 표시한다.
- 이벤트 스테이지를 사용하는 사건은 `content_stream`의 Story → Choice → Result 순서를 따르며, Web/terminal renderer는 코어가 준 순서를 표시만 한다.

## Outcome에 기록할 수 있는 runtime 효과

- `resources`, `danger`, `experience`, `set_trait`
- `add_flags` / `remove_flags`, `add_clues`, `add_items` / `remove_items`
- `destination_id`, `log`, 선택적 `presentation`
- Slice 3 이후 유효한 `add_insights`: 15. 기연 DB의 `기연 ID`만 참조하며 중복 획득은 무시한다.

## Slice 3 선택적 메타

- `runtime.leveling.thresholds`는 비어 있지 않고 오름차순이어야 한다. 문턱을 넘은 수만큼 수련 포인트가 생기고, `train:{ability_id}`가 같은 턴에 능력치를 1 올린다(최대 5).
- 번들 상위 `insights`는 `id`, 이름, 설명, 선택적 판정 보너스(+1~+2)를 정의한다. `1d91db2`에서 기연 3개와 `add_insights` outcome 연결을 커밋했고 D2 검증을 통과했다. Notion 15번 DB의 설계 행과 내용이 달라 DB 행의 `구현됨` 전환은 별도 reconcile 이후로 둔다.

## 카드 작성·승격 체크 추가

- 플레이어에게 노출되는 판정에는 능력치/난이도와 성공 확률을 함께 기록한다.
- 경험치/칭호/기연/아이템 효과를 카드 메모에만 쓰지 말고 outcome 필드로 명시한다.
- Notion 카드 DB의 `설계`는 runtime 구현을 뜻하지 않는다. YAML 변환, bundle/export 검증, Rust/WASM/Web parity가 완료된 뒤에만 `구현됨`으로 전환한다.
