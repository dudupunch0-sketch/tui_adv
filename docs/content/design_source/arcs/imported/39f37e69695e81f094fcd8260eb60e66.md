# 사건 밀도 원칙

큰 사건 하나는 최소한 다음 흐름을 갖는다.

`setup → approach/foreshadow → event → choice → immediate result → aftermath → next hook`

모든 단계가 별도 encounter일 필요는 없다. 한 Event 안에서 여러 StoryStage, ChoiceStage, ResultStage를 순서대로 배치할 수 있다.

특히 다음 전환에는 브리지 사건을 우선 검토한다.

- 장소가 바뀌는 전환
- 시간이 하루 이상 건너뛰는 전환
- 새 인물이 핵심 인물로 등장하는 전환
- 선택 결과가 다음 phase를 결정하는 전환
- 큰 전투 직후
- 관계가 가까워지거나 멀어지는 전환
- 천기록/천외편린이 등장한 직후

# 현재 gap audit 초안

| 전환 | 의심되는 문제 | 우선 조사할 브리지 |
| --- | --- | --- |
| 첫 전투 → 서하린 구조/조사 | 부상과 공포가 다음 목적지로 빨리 덮일 수 있음 | 치료, 소지품 확인, 서하린이 구조를 결정한 이유, 주인공의 첫 거짓말/진술 |
| 청류문 입문 → 잡일/수련 | 장소에 도착했지만 “이곳에서 살기 시작했다”는 체감이 약할 수 있음 | 첫 식사, 잠자리, 빚/잡일 배정, 문파 사람들의 첫 인상 |
| 잡일/첫 겨루기 → 청류문 습격 | 현재 가장 유력한 중간 공백 후보 | 평범한 하루, 작은 수련 실패, 서하린과의 복기, 문파 외부 이상 징후 |
| 습격 → 루트 선택 | 큰 사건 뒤에 선택의 정서적 준비가 부족할 수 있음 | 부상자 확인, 잃은 것의 목록, 세 세력의 제안이 왜 매력적/위험한지 보여주는 장면 |
| 루트 선택 → 무명 중반선 | route opener가 사건 요약처럼 느껴질 수 있음 | 첫 루트 활동, 선택의 첫 비용, 동료에게 선택을 설명하는 장면 |
| 무명 사건군 → 보스/최종전 | 개별 사건은 있으나 감정적 누적이 약할 수 있음 | 무명의 변화가 청류문/서하린/주인공에게 실제로 영향을 준 결과 사건 |
| 최종전 → 후일담 | 현재 runtime 구조는 있으므로 우선순위 낮음 | 실제 플레이에서 결산이 충분히 읽히는지 확인 |

이 표의 “의심”은 아직 확정 결함이 아니다. 플레이테스트 로그와 사용자의 기억을 대조한 뒤 사건 추가, 조건 수정, Event 내부 Stage 확장 중 하나로 분류한다.

# 09 사건 카드 작성 계약

각 신규 또는 보강 카드는 아래 항목을 반드시 채운다.

- `event_id`
- phase와 사건 역할: `main_forced`, `route_key`, `npc_relation`, `bridge`, `aftermath`, `ambient`
- 이전 사건과 진입 조건
- 이번 사건에서 플레이어가 새로 아는 것
- StoryStage / ChoiceStage / ResultStage 순서
- 선택별 즉시 결과와 장기 hook
- 다음 사건 또는 재합류 지점
- 안전한 관찰/후퇴/fallback
- runtime mapping 상태
- 플레이테스트 상태

# 작업 순서

1. 현재 플레이 경로에서 abrupt transition을 수집한다.
2. 위 gap audit의 후보를 실제 문제와 대조한다.
3. 전체 분기는 beat-level outline으로 먼저 채운다.
4. 가장 체감이 큰 공백 하나를 bridge Event로 설계한다.
5. 한 구간을 runtime에 반영하고 실제로 플레이한다.
6. 결과를 기준으로 다음 구간의 사건 밀도를 조정한다.
7. 확정된 카드만 09 DB와 repo runtime에 각각 반영한다.

# 인터뷰 결과 — 확정 방향

2026-07-16 사용자 플레이테스트 인터뷰를 반영했다.

- 가장 큰 공백은 서하린과 만나 청류문에서 수련을 시작한 뒤 혈월교 습격으로 넘어가는 구간부터 후반 전체에 걸친 사건 간 전환이다.
- 문제 원인은 메인 사건 사이의 **청류문 일상**, **서하린 관계 장면**, **훈련 전투**, **짧은 사이드 퀘스트**, **랜덤 인카운터**가 부족한 것으로 본다.
- 천기록은 자주 노출하지 않는다. 천기록의 희소성을 유지하면서, 청류문 생활과 인간 관계가 이야기의 기본 리듬을 담당한다.
- 메인 스토리는 긴 장면과 대화 중심으로 만든다.
- 사이드 스토리와 랜덤 인카운터는 짧고 촘촘하게 배치한다.

# 서하린 관계 연출 원칙

서하린은 단순히 친절하거나 쉽게 호감도를 올리는 인물이 아니다. 기존 상세 설계의 핵심인 소속감 / 외로움 축을 다음 행동으로 보여준다.

- 먼저 다가오지는 않지만, 주인공의 자리를 조용히 마련한다.
- 감정을 설명하기보다 식사, 붕대, 수련 시간, 비워둔 자리를 통해 표현한다.
- 플레이어가 서하린을 좋아하게 되는 이유는 “항상 다정해서”가 아니라, 무뚝뚝한 사람이 드물게 보여주는 돌봄이 누적되기 때문이다.
- 관계 장면에는 호감도 숫자보다 새로운 행동, 말투, 자리 배치, 다음 사건의 동행 여부를 우선한다.
- 서하린을 메시지 전달자나 튜토리얼 설명자로만 사용하지 않는다.
- 로맨스를 즉시 확정하지 않는다. 먼저 “이 사람 곁에 있고 싶다 / 이 사람이 떠나지 않았으면 한다”는 소속감이 쌓여야 한다.

# phase별 사건층 확장 기준

# 전환 밀도 규칙

- 큰 메인 사건을 두 개 연속으로 배치하지 않는다. 중간에 생활, 관계, 복기, 이동 중 하나가 있어야 한다.
- 큰 사건 직후에는 반드시 aftermath를 둔다. 승리/패배 결과만 보여주고 다음 phase로 넘기지 않는다.
- 메인 사건 사이에는 선택적 사이드 또는 랜덤 사건이 최소 하나 들어갈 수 있는 여지를 둔다.
- 사이드 사건은 메인 진행을 막지 않되, 보았을 때 다음 메인 장면의 대사·관계·상태 중 하나가 달라져야 한다.
- 랜덤 인카운터는 세계를 넓히는 역할이며, 핵심 진실을 독점하지 않는다.
- 같은 인물을 여러 번 만날 때는 같은 정보의 반복이 아니라 태도·거리·행동이 변해야 한다.
- 천기록은 희소한 전환점으로 남기고, 생활 공백을 천기록으로 메우지 않는다.

- 비어 있는 수련 대련표는 수련장 첫 패배와 복기로 이어지는 선택적 전투 전단계가 명확하다.
- 약재 창고의 빈칸과 습격 전날의 이상 징후는 생활 결핍과 외부 압박을 분리해 보여준다.
- 습격 직후에는 즉시 route를 열지 않고 회복·손실 확인을 거치도록 설계되어 사용자 방향과 일치한다.

## 수정 필요 후보

1. wuxia_cheongryu_raid_aftermath_roll_call과 wuxia_bridge_raid_aftermath_nameplates가 모두 습격 직후 피해자 확인과 route 선택 지연을 담당한다. 한쪽을 긴 메인 aftermath, 다른 쪽을 짧은 관계/행동 변주로 명확히 분리하거나 통합해야 한다.
2. wuxia_bridge_training_partner_absent는 ‘맡는다’ 선택에서 전투가 발생한다고 되어 있으나, 승패·부상·미해결 부채가 다음 카드에 전달되는 조건을 더 명시해야 한다.
3. wuxia_cheongryu_raid_omen의 선택 결과와 wuxia_bridge_raid_rain_tracks의 전조 정보가 중복되지 않는지, 최종 검수에서 정보 공개량을 비교해야 한다.

## 1차 판정

구간의 정서적 공백은 후보 사건으로 상당 부분 보강되었다. 현재 확정 결함은 아니며, 중복 2건과 조건 명시 1건을 일괄 수정 대상으로 유지한다. 카드 상태는 모두 초안으로 보존한다.

# 통합 검수 2차 결과 — 루트 선택 이후·무명·최종 준비

검수 대상: 루트별 가치관 사이드 6개, 무명 오독·실패 사건, 최종 증거·천기록 비노출 사건, 기존 무명/보스 메인 카드.

## 확인된 연결

- 루트별 6개 사건은 각각 청류문·귀환·정착·흑사방·무림맹·천기록의 생활 비용 또는 태도를 다르게 보여준다.
- 확인한 카드들은 모두 메인 루트를 차단하지 않고 정보·관계·증거·침식 상태만 변주한다.
- 무명 오독 사건은 핵심 진실을 독점하지 않고, 재회 신뢰도와 후속 대사만 바꾸는 구조다.
- 최종 증거 누락과 천기록을 펼치지 않는 선택은 실패·비사용 회차에도 최종 준비로 재합류하는 안전장치가 있다.
- 후일담 카드 연결이 각 route 카드에 지정되어 있어 결산으로의 hook은 존재한다.

## 수정 필요 후보

1. 루트별 가치관 카드의 본문이 현재 매우 짧다. 최종 검수 때 각 카드에 최소 한 개의 즉시 결과와 한 개의 다음 메인 대사 hook을 추가해야 한다.
2. 흑사방의 빚 문서 한 줄은 미해결 부채 보유가 필수이므로, 부채가 없는 흑사방 회차의 대체 route 사건이 필요할 수 있다. 메인 진행을 막지는 않지만 후보 풀의 공백을 확인한다.
3. 천기록을 펼치지 않는 선택은 천기록 관련 사건 직후 조건이므로, 천기록을 전혀 보지 않은 회차와 ‘한 번 본 뒤 덮은 회차’를 구분할 필요가 있다.
4. 무명 오독·잘못 짚은 무명·빈 의자 연쇄는 모두 무명 신뢰도 변주를 사용하므로, 동일 회차에서 중복 발생하지 않는 seen/type 배제가 필요하다.

## 2차 판정

루트 차별성과 메인 복귀 구조는 현재 초안으로 충분히 성립한다. 다만 route 카드 본문 밀도, 부채 없는 흑사방 대체 후보, 천기록 노출 상태 구분, 무명 중복 방지 태그는 확정 전 수정 대상으로 남긴다.

# 통합 검수 3차 결과 — 후일담·다회차·실패 fallback

검수 대상: 후일담 잔상 6개, 사이드 연쇄 회수 6개, 환경·이동 랜덤 사건의 후일담 연결, 실패·후퇴 fallback 6개, 시드 운영 매트릭스.

## 확인된 연결

- 후일담 사건은 청류문·서하린·무명·귀환·정착 상태를 소비하며, 엔딩 자체를 새로 덮어쓰지 않는 구조다.
- 같은 노래, 빈 보따리, 빈 의자, 편지 등 반복 모티프가 1회차의 선택을 후일담에서 변주하므로 다회차 유도 목적에 부합한다.
- 사이드 연쇄는 1차 사건을 본 시드에서만 열리도록 선행 조건을 둔다.
- 실패·후퇴 사건은 사망이나 강제 루트 이탈 대신 부상·소문·부채·정보 부족으로 전환하고, 최종전 또는 후일담으로 재합류한다.
- 운영 매트릭스에 seen, 연쇄 조건, 유형 반복 방지, 메인 복귀 안전장치가 기록되어 있다.

## 수정 필요 후보

1. 후일담 카드 연결값 중 일부가 제목 텍스트와 사건 ID를 혼용한다. 최종 확정 전 모든 연결을 사건 ID 기준으로 통일해야 한다.
2. 후일담 랜덤 사건이 한 회차에서 여러 개 당첨될 경우, 첫 장면이 중복될 수 있으므로 후일담 슬롯을 0~1개로 제한하는 규칙을 runtime 계약에 명시해야 한다.
3. 실패 fallback의 ‘재합류’ 지점은 카드 메모에 존재하지만, 실제 runtime 조건 필드에는 아직 구현되지 않았다. 구현 전환 시 fallback_to와 preserve_state 목록을 별도 필드로 옮겨야 한다.
4. 115개 후보는 설계 초안이며 runtime 미반영이다. 현재 상태에서 플레이 가능성을 증명하는 것은 카드 수가 아니라, 대표 Event 승격 후 실제 시드 재생 테스트다.

## 3차 판정

후일담·다회차·실패 복구의 설계 방향은 충족한다. 남은 핵심 위험은 연결 ID 정규화, 후일담 슬롯 상한, fallback 상태 전달, runtime 미구현이다.
