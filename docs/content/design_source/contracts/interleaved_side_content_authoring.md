# 장간 교차형 사이드 콘텐츠 저작 계약

status: canonical

`runtime_status: design_only`은 이 문서가 앞으로의 SQ·RI 저작 기준이라는 뜻이다. scheduler, 저장 상태, 이벤트 선택기, 보상 지급 코드가 이 계약을 구현했다는 뜻은 아니며, runtime 반영 전에는 이 문서의 handoff 후보 필드를 실제 스키마와 대조하고 별도 구현·검증 승인을 받아야 한다.

## 1. 목적, 범위, 비범위

이 계약은 메인 스토리 장 사이에 여러 독립 사이드 퀘스트와 랜덤 인카운터를 불규칙하게 교차 배치할 때도 각 장면이 자연스럽게 시작하고 안전하게 끝나도록 하는 범용 저작 정본이다. 기본 플레이 모델은 메인 1장이 끝난 뒤 활성 SQ 1~2개의 현재 장과 RI 약 7개가 순서를 섞어 등장하고, 그 뒤 다음 메인 장으로 넘어가는 흐름이다.

활성 SQ 1~2개와 RI 약 7개는 플레이 리듬을 설명하는 기대 밀도다. 고정 quota나 완료 조건이 아니며, 플레이 시간, 지역 적합성, 중복 억제, 접근성, 난이도에 따라 늘거나 줄 수 있다. 콘텐츠는 실제 순서와 간격이 달라도 성립해야 한다.

적용 범위는 다음과 같다.

- 새로 저작하거나 대규모 개정하는 모든 SQ line, SQ chapter, RI
- 메인 chapter 사이에서 scheduler가 후보를 섞어 뽑는 콘텐츠
- 여러 SQ가 동시에 활성화되고 RI가 그 사이에 삽입되는 콘텐츠
- 중도 이탈, 장기 지연, 누락 재후보, 중복 호출을 견뎌야 하는 콘텐츠

다음은 이 계약의 비범위다.

- 메인 스토리 chapter 내부의 고정 연출 순서
- 한 세션에서 끊김 없이 진행하도록 별도 승인된 던전·보스 연전
- runtime scheduler 알고리즘, 저장 포맷, 확률·쿨다운의 확정 수치
- 이벤트 YAML, 코드, 번들 구현 완료 선언
- 특정 storypack의 세계관, 인물, 보상 수치 자체

## 2. 용어

| 용어 | 정의 |
|---|---|
| main chapter | 메인 스토리의 한 장. SQ·RI 배치 구간을 나누는 기준점이지만 사이드의 필수 플래그 제공자가 아니다. |
| 메인 구간 | 한 main chapter 종료 뒤 다음 main chapter 시작 전까지의 교차 배치 구간. |
| SQ line | 하나의 독립 주제와 누적 선택, 여러 결말을 가진 사이드 퀘스트 전체. |
| SQ chapter | SQ line을 이루는 한 번의 플레이 단위. 이전 문서의 beat도 scheduler에 들어갈 때는 독립 chapter로 취급한다. |
| RI | Random Encounter. 한 번의 이벤트에서 진입, 선택, 즉시 위기, 퇴장을 끝내는 독립 장면. |
| local goal | 해당 SQ chapter 또는 RI 안에서 시작하고 끝내는 단일 목표. |
| local state | 해당 사이드 콘텐츠가 소유하는 변수·관계·지역 상태. 메인 필수 진행 상태와 분리한다. |
| safe closure | 플레이를 그 자리에서 종료해도 사람, 유해, 단서, 장소에 즉시 대응이 필요한 위험이 남지 않는 종료. |
| durable anchor | 장간 지연 뒤에도 다음 chapter를 찾고 이해하게 하는 지도, 편지, 기록, 봉인 물건, 안전 custody, 약속, 공고 같은 지속 연결물. |
| resume condition | durable anchor와 local state를 바탕으로 다음 chapter가 후보가 되는 명시 조건. |
| fallback | 실패, 취소, 연결 끊김, 이탈 때 긴급 상황을 닫고 재개 가능한 안전 상태로 수렴시키는 대체 결과. |

## 3. Scheduler 저작 계약

저자는 scheduler가 다음 조건으로 콘텐츠를 호출한다고 가정한다.

- **순서 비보장:** 서로 다른 SQ chapter와 RI의 상대 순서는 보장되지 않는다. 한 SQ의 두 chapter 사이에 다른 SQ, RI 여러 개, main chapter가 들어갈 수 있다.
- **같은 SQ 제한:** 같은 메인 구간에는 같은 SQ line의 chapter를 최대 1개만 배치한다. 같은 라인의 연속 chapter를 한 구간에 압축하지 않는다.
- **누락 재후보:** 예정 chapter가 뽑히지 않으면 완료로 간주하거나 다음 chapter를 앞당기지 않는다. 미완료 chapter를 다음 적합 구간의 후보로 되돌린다.
- **중복 호출:** 완료 chapter는 본문을 다시 진행하지 않는다. 완료 recap, 현재 anchor, 보상 수령 상태만 보여 주고 안전하게 종료한다. RI는 자체 재등장 정책에 따른 짧은 변주만 허용한다.
- **도중 이탈:** 선택 확정 전 이탈은 명시된 fallback으로 수렴한다. 재개 시 이미 닫힌 긴급 장면을 반복하지 않고 recap과 남은 local goal에서 시작한다.
- **라인 포기:** 포기는 현재 chapter의 safe closure 뒤에만 확정한다. 후속 anchor를 비활성화하고 비긴급 로컬 후일 상태만 남긴다.
- **메인 변화 내성:** main chapter 번호나 총 장수가 바뀌어도 작동해야 한다. 진입 시점은 `초반`, `초중반`, `중반 이후`, `결말 전 제외` 같은 범주와 로컬 조건으로 표현한다.
- **메인 독립:** main chapter 완료 여부는 배치 창을 여는 일반 신호일 수 있지만, 특정 메인 선택·진엔딩·핵심 인물 관계를 SQ·RI의 필수 해금 키로 삼지 않는다. 예외 승격은 별도 승인 대상이다.

권장 흐름은 `main chapter → RI/SQ/RI/다른 SQ/RI 묶음 → 다음 main chapter`다. 이는 예시이지 고정 순서가 아니다. scheduler가 일부 후보를 생략하거나 간격을 늘려도 서사가 깨지지 않아야 한다.

## 4. SQ line 및 chapter 필수 계약

### 라인 수준 필수 요소

모든 SQ line은 다음을 기록한다.

1. 독립 진입 훅과 로컬 NPC·세력
2. 중심 주제, 누적 선택 변수, chapter 순서
3. 권장 main 배치 폭과 범주형 최소·최대 장간 공백
4. 중도 이탈과 명시적 포기 처리
5. 실패해도 지속 가능한 로컬 상태
6. 최소 3개의 구별되는 결말과 배타·변주 보상
7. 재플레이 호기심과 중복 재생 정책
8. 메인 필수 진행·진엔딩과의 의존성 등급

### Chapter 수준 필수 요소

모든 SQ chapter는 아래 요소를 빠짐없이 가진다.

1. **복귀 1~2문장:** 이전 선택과 현재 durable anchor를 짧게 되짚는다. 첫 chapter는 진입 소문·의뢰를 되짚는다.
2. **단일 local goal:** 이번 chapter 안에서 판정 가능한 목표 하나를 둔다.
3. **긴급성 same-chapter closure:** 전투, 추격, 활성 재난, 인질, 시간제한 같은 위기는 승패와 무관하게 이번 chapter 안에서 닫는다.
4. **종료 안정점:** 인물, 부상자, 유해, 물건, 장소, 판정이 어디에 어떤 안전 상태로 남는지 쓴다.
5. **durable next anchor:** 다음 chapter가 늦게 와도 남는 연결물을 쓴다.
6. **재개 조건:** 어느 상태와 anchor가 다음 후보를 여는지 쓴다.
7. **실패 fallback:** 실패·취소·이탈 때 도달하는 안전 상태와 이후 선택 가능성을 쓴다.

한 chapter 안에 1~2개의 핵심 장면과 짧은 연결 사건을 둘 수 있다. 장면 수가 아니라 local goal과 긴급성의 닫힘이 chapter 경계를 결정한다.

### 복사 가능한 SQ line 양식

```markdown

- 제목/주제:
- 독립 진입 훅:
- 로컬 NPC·세력:
- chapter 순서:
- 누적 선택 변수:
- 권장 main 장 배치 폭:
- 최소 장간 공백 범주:
- 최대 장간 공백 범주:
- 중도 이탈/포기 정책:
- 실패 지속 상태:
- 결말 3개 이상:
- 보상/배타 관계:
- 재플레이 호기심:
- 메인 의존성: 독립
```

### 복사 가능한 SQ chapter 양식

```markdown
### {sq_chapter_stable_id}

- 복귀 문장: 이전 선택과 현재 anchor를 1~2문장으로 요약한다.
- 이번 장 local goal/장면: 이번 장에서 시작하고 끝낼 목표 하나를 쓴다.
- 선택 ①과 즉시 결과:
- 선택 ②와 즉시 결과:
- 선택 ③과 즉시 결과:
- 긴급성 closure: 활성 위기의 종료 결과를 선택별 또는 공통으로 쓴다.
- 종료 안정점: 인물·유해·단서·장소의 안전 상태를 쓴다.
- 다음 durable anchor: 장기 지연에도 남는 연결물을 쓴다.
- 재개 조건: 다음 chapter 후보화에 필요한 local state와 anchor를 쓴다.
- 실패/이탈 fallback: 즉시 위험 없이 닫히는 대체 상태를 쓴다.
- local state 변경:
- 보상 또는 결말 연결:
```

## 5. 긴급성 경계

| 같은 chapter에서 반드시 닫을 것 | 장간 유지 가능한 것 |
|---|---|
| 시작된 전투와 결투 | 지도와 이미 확인된 경로 |
| 진행 중인 추격과 도주 | 배달 완료된 편지와 답신 약속 |
| 번지는 화재·홍수·역병 같은 활성 재난 | 회의록, 판정문, 장부, 목격 기록 |
| 현재 억류 중인 인질과 즉시 처형 위협 | 봉인되어 인계된 물건과 비부패성 증거 |
| 노출되거나 운구 중 위험에 놓인 시신 | 중립 사당·유족·봉인 관의 안전 custody |
| 치료받지 못한 부상자와 구조 대기자 | 날짜가 넉넉한 약속, 소환장, 경기 공고 |
| 초·횟수·당일 마감이 진행 중인 시간제한 | 소문, 가격, 평판, 로컬 인물·단체 호감도 |
| 썩거나 지워지거나 곧 소멸하는 필수 단서 | 사본이 남은 기록, 보존 처리된 표본, 등록된 표식 |

`후일 다시 싸운다`, `며칠 뒤 복수를 논한다`, `가격이 오른다` 같은 상태는 현재 위기가 종료되고 새 사건의 후보만 남는다면 장간 유지가 가능하다. 반대로 `적이 달아났으니 즉시 쫓아야 한다`, `환자가 계속 늘고 있다`, `시신을 들고 다음 이벤트를 기다린다`는 표현은 safe closure가 아니다.

### 예외 승인

긴급성을 chapter 밖으로 넘기는 설계는 일반 SQ·RI 예외로 승인하지 않는다. 끊김 없는 연전이나 탈출처럼 활성 위기 자체가 플레이 모드인 경우에는 해당 콘텐츠를 이 scheduler의 일반 후보에서 분리하고, arc 문서에 다음을 모두 기록해 authoring owner와 scheduler handoff owner의 명시 승인을 받아야 한다.

- 예외가 필요한 서사·플레이 이유
- 적용되는 line/chapter와 최대 지속 범위
- 중단·접속 종료 시 즉시 적용할 safe closure 대안
- 일반 scheduler 후보에서 제외하는 방식
- 저장·재개·실패 상태의 runtime handoff 영향

승인 기록이 없거나 safe closure 대안이 없으면 FAIL이다.

## 6. RI 필수 계약

RI는 한 번의 이벤트에서 이해·선택·즉시 위기·퇴장을 끝낸다.

- 선택은 3개를 권장한다. 선택 수가 다르면 가독성, 비용, 보상 변별 이유를 기록한다.
- 각 선택은 immediate crisis를 이벤트 안에서 닫는다.
- 모든 선택 뒤에 인물·장소·물건의 stable exit를 명시한다.
- delayed result는 소문, 가격, 로컬 호감도, 비긴급 지역 상태, 재등장 대사·보상 변형만 허용한다.
- 추격, 전투, 구조, 치료, 운구, 타이머를 다음 이벤트의 의무로 넘기지 않는다.
- main chapter나 SQ chapter의 필수 단서·필수 보상·필수 인물을 RI에 숨기지 않는다.
- 다른 콘텐츠와 연결되더라도 bonus recap, 추가 대사, 선택 보상 변형만 허용한다.
- 미완료 SQ를 우회 완료하거나 main gate를 여는 RI는 명시적 승격 승인 없이는 금지한다.

### 복사 가능한 RI 양식

```markdown
### {ri_stable_id}

- 제목/유형:
- 조건/재등장:
- 상황/local goal:
- 선택 ①:
- 선택 ②:
- 선택 ③:
- 즉시 결과: 각 선택의 immediate crisis closure를 쓴다.
- 지연 결과: 비긴급 로컬 상태만 쓴다.
- 보상: 분류·등급·배타 관계 또는 메타 재화 규칙을 쓴다.
- local state/플래그:
- 종료 안정점: 사람·물건·장소의 stable exit를 쓴다.
- 재등장/후속 허용: bonus only 범위를 쓴다.
- 의존성: main/SQ 필수 단서 없음.
- 모티브/의미:
```

## 7. 의존성과 보상

### 의존성 기본값

- SQ·RI는 메인 진엔딩, 메인 필수 진행, 핵심 인물 생존·호감도와 독립한다.
- 메인 chapter는 일반 배치 창만 제공하며 특정 메인 선택을 필수 조건으로 만들지 않는다.
- 사이드 결과가 메인으로 승격되려면 arc 문서에 읽기·쓰기 플래그, 누락 시 대체 경로, 진엔딩 영향, safe closure를 적고 별도 승인을 받아야 한다.
- 승격 전 설계는 `design_only`이며 runtime 구현 완료로 표현하지 않는다.

### 보상 규칙

보상 종류와 등급 의미는 [보상 시스템 설계 원칙](../arcs/imported/3a037e69695e8175ab82f86db074c265.md)을 참조한다. 사용 가능한 분류는 스킬, 기연, 칭호, 인물 호감도, 단체 호감도, 아이템·소모품, 퀘스트 아이템, 패물(佩物), 기억 파편이다. 기억 파편은 이름·희귀도가 붙는 일반 아이템이 아니라 별도 계정 귀속 메타 재화다.

- 중요한 선택 보상은 대체로 배타적이며 선택의 가치와 비용을 함께 드러낸다.
- 전설 등급은 단순 상위 수치가 아니라 명시적 trade-off를 가진다.
- 독립 콘텐츠의 호감도는 기본적으로 로컬 인물·단체에만 적용한다.
- 실패·후퇴·포기도 무보상 대신 다른 정보, 관계, 기록, 소형 보상, 지역 상태를 줄 수 있다.
- 실패 결과가 즉시 추격, 강제 전투, 치료되지 않은 부상, 갚지 않으면 진행 불가인 urgent debt를 만들면 안 된다.
- 퀘스트 아이템이 후속을 열더라도 안전하게 보관되고, 분실 시 recap·사본·보관소 조회 같은 대체 경로가 있어야 한다.

## 8. 생성 파이프라인

1. **모티브 분해:** 원전·주제·아이디어를 인물명이 아니라 갈등, 가치 충돌, 선택 비용, 공동체 결과로 분해한다.
2. **RI/SQ 분류:** 한 장면에서 닫히는 사건은 RI, 누적 선택과 여러 결말이 필요한 사건은 SQ line으로 분류한다.
3. **라인 skeleton:** SQ의 진입, chapter 순서, 누적 변수, 최소 3결말, 포기·실패 지속을 먼저 쓴다.
4. **Chapter boundary test:** 각 chapter의 local goal과 활성 긴급성을 표시하고, chapter 끝에서 모두 닫히는지 확인한다.
5. **Anchor 설계:** 다음 chapter가 늦어져도 남는 durable anchor와 분실·누락 fallback을 정한다.
6. **선택·보상 설계:** 선택이 서로 다른 가치·비용·즉시 결과를 만들고 보상 taxonomy와 맞는지 확인한다.
7. **Interleaving playtest:** main chapter, RI 여러 개, 다른 SQ를 사이에 삽입하고 recap·재개 가능성을 읽어 본다.
8. **Authoring review:** 아래 검수 테스트와 checklist를 통과한 뒤 runtime handoff 대상으로 표시한다.

### 대량 생성 중복 방지 축

20개 이상의 RI나 여러 SQ를 한 번에 만들 때는 ID 중복뿐 아니라 의미 중복을 검사한다. 아래 축을 표로 놓고 인접 항목이 같은 조합을 반복하지 않게 한다.

- 핵심 모티브와 질문
- 갈등 주체와 NPC 역할
- 장소·시간대·감각 정보
- 대화형·전투형·탐색형·복합형 같은 상호작용 유형
- 3선택의 구조와 도덕적 비용
- 즉시 결과와 delayed state 축
- 종료 안정점과 anchor 유형
- 보상 분류·등급·이름 톤
- 감정적 종결: 화해, 유예, 애도, 판정, 손실 수용, 폭로 등

이름만 다르고 선택 구조·결과·의미가 같은 항목은 중복으로 판정해 합치거나 재구성한다.

## 9. 검수 테스트와 판정

| 테스트 | 실행 방법 | PASS | FAIL |
|---|---|---|---|
| delay test | SQ chapter 사이에 main chapter 1개와 RI 7개를 삽입해 읽는다. | 복귀 1~2문장과 anchor만으로 인물·목표·이전 결과를 이해한다. | 즉시 전투·추격·구조를 기억하거나 계속해야 이해된다. |
| reorder test | 다른 SQ chapter와 RI를 앞뒤로 교차한다. | 상대 순서가 바뀌어도 local state와 선택 의미가 유지된다. | 다른 콘텐츠가 먼저 나와야 필수 인물·단서가 생긴다. |
| stop test | 각 chapter와 RI의 마지막 문장에서 플레이를 종료한다고 가정한다. | 사람·유해·부상자·장소·단서에 즉시 위험이 없다. | 노출 시신, 미치료 부상, 진행 중 전투·재난·타이머가 남는다. |
| abandonment test | 각 선택 전후에 라인을 포기한다. | fallback으로 안전하게 닫히고 메인 진행이 막히지 않는다. | 포기하면 긴급 상황이나 필수 플래그 공백이 남는다. |
| missing chapter test | 예정 chapter 한 번을 scheduler에서 누락한다. | 같은 chapter가 재후보가 되고 다음 chapter는 앞지르지 않는다. | 누락이 완료 처리되거나 이후 chapter가 필수 정보를 가정한다. |
| duplicate event test | 완료 SQ chapter와 RI를 다시 호출한다. | recap·변주·보상 상태 확인만 하고 중복 지급·위기를 만들지 않는다. | 본문·전투·일회 보상이 다시 실행된다. |
| no hidden gate test | 모든 main/SQ 필수 단서와 플래그 출처를 추적한다. | RI를 보지 않아도 main과 SQ 필수 경로가 성립한다. | 선택적 RI 안에 필수 단서·인물·진엔딩 조건이 숨어 있다. |

하나라도 FAIL이면 `authoring_review_required`를 유지하고 runtime handoff 대상으로 넘기지 않는다. 문장 수정만으로 안전 상태를 입증할 수 없으면 chapter 경계를 다시 나눈다.

## 10. Worked examples

### SQ chapter: 적장 시신 반환

- **복귀:** 중립 사당이 적장의 신원 증표와 봉인 관을 안전하게 맡고 있다. 유족의 확인 편지가 도착했다.
- **local goal:** 낮 동안 유족 대표와 반환 조건을 합의하고 custody를 확정한다.
- **선택:** 공개 반환, 중립 사당 입회 반환, 신원 증거만 먼저 교환 중 하나를 택한다.
- **same-chapter closure:** 이동 중 습격이 발생하면 그 자리에서 격퇴·협상·우회 중 하나로 끝내고, 시신은 유족 또는 중립 사당의 봉인 관에 인계한다.
- **종료 안정점:** 시신을 든 채 다음 chapter를 기다리지 않는다. 부상자는 치료되고 추격은 종료된다.
- **anchor/resume:** 유족이 보낸 후일 답신과 사당 인계 기록이 복수 논쟁 chapter를 연다. 답신이 늦어져도 custody는 유지된다.

이 예시의 핵심은 운구를 여러 장에 걸쳐 계속하는 것이 아니라, 각 chapter가 안전 custody에서 시작해 안전 custody로 끝나는 데 있다.

### RI: 강이 되받아친 칼

- **상황:** 분노한 무인이 강을 훼손하자 급류가 나루와 행인을 덮친다.
- **3선택:** 무인을 제압한다, 떠내려가는 사람부터 구한다, 둑의 장애물을 치운다.
- **즉시 종료:** 어느 선택이든 사람을 물 밖으로 옮기고 무인을 제압·퇴각시키며 나루를 임시 폐쇄한다. 진행 중 홍수나 추격을 남기지 않는다.
- **stable exit:** 행인은 치료소, 무인은 포박소 또는 먼 퇴각로, 나루는 관리인의 통제 아래 있다.
- **delayed result:** 이후에는 나루 통행료, 강변 주민의 로컬 호감도, 강을 두려워하는 소문만 바뀐다.

이 예시는 자연의 반격을 큰 사건으로 보이게 하면서도 다음 이벤트에 구조·추격 의무를 넘기지 않는 RI 경계를 보여 준다.

## 11. 권한과 우선순위

이 문서는 effective date 이후 새로 만드는 SQ·RI와 대규모 개정의 기본 authoring contract다. 특정 arc 문서는 세계관, ID, 인물, 선택, 보상, 자체 checklist를 더 엄격하게 정의할 수 있지만 이 계약의 safe closure와 필수 단서 독립성을 말없이 약화할 수 없다.

특정 arc가 예외를 요구하면 해당 arc 문서에 예외 사유, 적용 범위, 중단 시 안전 종료 대안, scheduler 격리 방식, 승인 주체를 기록해야 한다. 승인되지 않은 예외는 범용 계약이 우선한다. 기존 arc가 이 문서를 링크하지 않았다는 이유만으로 이미 runtime 준수·구현이 완료됐다고 간주하지 않는다.

첫 준수 사례는 [일리아스 파편형 독립 사이드 콘텐츠 v1](../arcs/iliad_fragmented_side_content_v1.md)이다. 이 사례는 범용 계약을 대체하지 않으며, 자체 상세 규칙과 콘텐츠 데이터를 함께 보존한다.

## 12. Authoring checklist

- [ ] 활성 SQ 1~2개, RI 약 7개가 기대 밀도이며 고정 quota가 아님을 문서가 가정한다.
- [ ] 같은 SQ는 한 메인 구간에 최대 1 chapter만 후보가 된다.
- [ ] 각 SQ line에 독립 진입, 누적 변수, 배치 폭, 포기·실패, 3결말 이상이 있다.
- [ ] 각 SQ chapter에 복귀 문장, 단일 local goal, 긴급성 closure, 종료 안정점, durable anchor, 재개 조건, fallback이 있다.
- [ ] 각 RI가 한 이벤트에서 immediate crisis와 stable exit를 끝낸다.
- [ ] delayed result가 소문·가격·로컬 호감도·비긴급 지역 상태로 제한된다.
- [ ] 노출 시신, 미치료 부상자, 활성 전투·추격·재난·인질·타이머가 장 끝에 남지 않는다.
- [ ] 부패·소멸 가능한 필수 단서를 장간 anchor로 쓰지 않는다.
- [ ] RI에 main/SQ 필수 단서나 진엔딩 gate가 없다.
- [ ] 실패·이탈·포기 결과도 안전하고 main 진행을 막지 않는다.
- [ ] 중복 호출이 본문·보상·위기를 다시 실행하지 않는다.
- [ ] reward taxonomy, 배타 관계, 전설 trade-off, 기억 파편 규칙이 맞는다.
- [ ] ID와 의미 중복을 모두 검사했다.
- [ ] delay, reorder, stop, abandonment, missing chapter, duplicate event, no hidden gate 테스트가 모두 PASS다.
- [ ] arc 예외가 있다면 사유·범위·안전 종료 대안·승인 기록이 있다.
- [ ] 문서 상태가 runtime 구현 완료를 과장하지 않는다.

## Runtime handoff field 후보

아래는 authoring에서 scheduler/runtime로 넘길 의미 단위다. 실제 필드명과 자료형은 runtime 설계에서 확정하며, 이 목록 자체는 구현 스키마 선언이 아니다.

| 의미 | handoff에 필요한 내용 |
|---|---|
| content identity | stable content ID, 콘텐츠 종류(SQ line/SQ chapter/RI), authoring version |
| line ordering | line ID, chapter 순서, 선행 chapter 완료 조건 |
| eligibility | 로컬 진입 조건, 권장 main 배치 폭, 지역·시간 조건 |
| density hints | 활성 SQ 기대 범위, RI 기대 밀도, 같은 SQ 구간당 최대 1장 |
| local state | 읽기·쓰기 변수, 허용 값, 초기값, 결말 상태 |
| completion | 완료·포기·실패·중복 호출의 idempotent 처리 |
| closure | immediate crisis 종료 여부, 종료 안정점, fallback state |
| continuation | durable anchor, resume condition, 누락 재후보 정책 |
| replay | RI 재등장 쿨다운 의미, recap·변주·중복 보상 정책 |
| delayed effects | 허용된 비긴급 소문·가격·로컬 호감도·지역 상태 |
| dependencies | main/SQ 필수 단서 없음 또는 승인된 승격 기록 |
| rewards | reward taxonomy 참조, 배타 그룹, 지급 시점, 중복 전환 |
| review | authoring review 상태, 예외 승인 주체, 검수 결과 |

handoff 시에는 각 SQ chapter와 RI가 위 의미를 실제 값으로 채웠는지 검토한다. runtime이 지원하지 않는 의미가 있으면 조용히 생략하지 않고 구현 범위 또는 authoring 제약으로 되돌려 합의한다.
